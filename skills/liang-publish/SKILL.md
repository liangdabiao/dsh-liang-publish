# 梁工 · 发布流程（v1：国内四平台）

> 工具分工：
> | 谁 | 做什么 |
> |---|---|
> | 本 skill（AI） | 读文章资料、写四平台文案、确认封面、建工程、生成 publish.json 并校验 |
> | liang_publish 工具 | make 生成工程校验 / plan 进计划 / run 后台自动填写上传页 / sync 取链接 |
> | bsk + 本机 Chrome | 打开各平台上传页、传视频封面、填文案设定时（只填写，最后的「发布」由人点） |
> | liang_data 工具 | 采流量、采粉丝、出复盘和周报 |

## 流程（按序，不跳步）

```
① 收资料 → ② 写发布素材 md → ③ 确认封面 → ④ 建工程目录 → ⑤ make 生成 publish.json 并校验
→ ⑥ plan 进分发计划 → ⑦ run 后台填写 → ⑧ 用户点国内平台的发布 → ⑨ sync 取链接回填
```

### ① 收资料

用户会给：**文章资料**（可能是一篇或多篇 markdown/文本/链接，也可能直接在对话里说）、**成片文件位置**（可自动上传视频的 mp4）。缺什么问什么，不要臆测。确定这一期：系列名、序号、标题、是否定时发布。

### ② 写发布素材 md

一期一个 md，章节名和加粗字段名必须按下面写，`make` 靠它们取文案：

```markdown
# 系列名 · 第 N 期｜本期标题

> 序号：N
> 定时发布：2026-11-20 18:00          ← 没有定时就删掉这行

## 二、B站
**标题：**
……（≤80 字）
**简介：**
……（开头一段介绍 → 章节 → 结尾，≤2000 字）
**标签：**
#账号名 #标签2 #标签3（≤10 个）

## 三、小红书
**标题：**
……（≤20 字）
**正文：**
……
#账号名 #话题2 #话题3（话题写在正文最后一行）

## 四、抖音
**标题：**
……（≤30 字）
**正文：**
……
#账号名 #话题2（话题最多 5 个）

## 五、视频号
**短标题：**
……（6–16 字）
**描述：**
……
#账号名 #话题2
```

写作规则（实战总结）：

- **只在 B站简介里放链接**（小红书、抖音、视频号不放链接、微信号、「去主页 / 评论区领 / 私信我」这类引导；不写海外模型和厂商名 Claude、ChatGPT、Gemini…，用 AI、Agent 代称。校验会拦，拦了就改）。
- 每个平台的第一个标签放账号名（`make` 传 `requireTag` 会检查）。
- 小红书写成「跟朋友讲这周干了啥」：为什么做、几个真实例子、踩过的坑；少 emoji、少清单。
- 四个平台的文案不是互拷：同一篇文章，B站偏章节化教程、小红书偏个人经验、抖音开头 3 秒抓人、视频号短标题带数字。

### ③ 确认封面（门禁）

写完文案先给 2–3 套封面文案让用户选，确认前不出图。出两张：竖 3:4（小红书、抖音、视频号主页）`封面/cover-3x4.png`、横 4:3（B站、抖音分享卡）`封面/cover-4x3.png`。主标题够大（手机缩略图一眼能读清）。

### ④ 建工程目录

```
<rootPath>/<系列>/<期>/
  成片.mp4            统一叫这个名字（必须 faststart，导出时加 -movflags +faststart）
  发布素材.md         ② 的备份
  封面/cover-3x4.png  cover-4x3.png（有哪个放哪个）
```

### ⑤ 生成 publish.json 并校验

调 `liang_publish(action="make", mdPath=..., dir=...)`。
返回 ❌ 就改 md 再 make，直到「✅ 校验通过」；⚠️ 逐条看一眼。某个平台这期不发，在 publish.json 里给它加 `"skip": "原因"`（或 make 后手动改）。

### ⑥ 进分发计划

`liang_publish(action="plan", dir=...)`——面板「梁工发布中控」出现这一期，平台都是「计划中」。

### ⑦ 开跑

`liang_publish(action="run", dir=...)`——后台任务开跑，面板看进度。跑之前建议先 `doctor` 体检登录态；跑的过程浏览器会自己动，提醒用户**别关 Chrome、别切走后台窗口里的标签页**。

- 四个平台都是**填好就停**：B站提示选「创作声明」，最后一下「发布 / 定时发布」由用户自己点（降低风控风险）。
- 防重：库里已到位（已填好/已定时/已发布）的平台不会再跑；确要重跑传 `force=true`，先去平台确认没发出去。
- 卡住/出错的平台：`run` 带 `only="平台id"` 单独补跑。

### ⑧ 用户点发布（四家全是）

点之前检查：能勾原创的都勾上（视频号「声明原创」、小红书「原创声明」、B站创作声明）；定时时间对不对。

### ⑨ 取链接、回填

到点后 `liang_publish(action="sync", id=...)`：写回工程目录 `发布记录.json`，面板刷新可见。平台认不出（标题改过）就 `liang_publish(action="mark", id=..., platform=..., url=...)` 人工标。

## 数据反馈（liang_data）

- `action="metrics"`：采各期流量（近 30 天已发布的期）。**要求本机 Chrome 开着且已登录**，没开着就当天跳过。
- `action="followers"`：采四平台粉丝（B站/抖音/小红书/视频号创作者后台）。
- `action="review", id=..., d=1/3/7`：单期复盘（各平台占比、互动率、和上一期同龄对比）。
- `action="weekly"`：周报。
- 定时采集：用户同意后用 dsh 定时任务（如每天 10:00 跑 metrics + followers + 到点 sync），任务里提示「浏览器没开就跳过」。

## 安全红线

- 只操作用户自己的账号；不做评论、点赞、私信、关注这类互动自动化。
- **同一条视频每个平台只上传一次**，失败了先去平台确认没发出去再重跑。
- **四家最后一下「发布」永远由人点**——这是产品底线，不是缺陷。
- 用户浏览器是本机日常 Chrome：不装东西、不改设置、不开无痕；自动化窗口在后台，尽量不打扰。
